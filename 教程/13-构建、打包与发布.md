# 13 · 构建、打包与发布：从 swift run 到 /Applications

> FocusPet 零基础开发教程 · 第 13 篇
> 对应源码：`Package.swift`（19 行）、`package-app.sh`（26 行）、`Sources/FocusPet/Info.plist`

到目前为止你写的代码都能用 `swift run` 跑起来。但 `swift run` 跑的是**裸可执行文件**——第 09 章说过，它连系统通知都用不了。要成为一个真正的 mac 应用，必须经过打包。本章把「编译 → 打包 → 部署 → 验证」整条链路走完。

---

## 一、先厘清三个名词

初学者最容易混淆的三个概念：

| 名词 | 是什么 | FocusPet 里的对应物 |
| --- | --- | --- |
| **SwiftPM 包（Package）** | 源码 + 构建清单的组织单位 | 整个 FocusPet 目录，`Package.swift` 是清单 |
| **可执行文件（Binary）** | 编译产物，一个 Mach-O 程序 | `.build/release/FocusPet` |
| **.app 包（Bundle）** | 目录伪装成的「应用」，系统认可的发布形态 | `FocusPet.app/`（内含可执行文件 + 资源 + 元数据） |

关键认知：**`.app` 不是编译出来的，是「组装」出来的**。编译只产出一个二进制文件；把它放进标准目录结构、配好元数据（Info.plist）、带上资源，才成为一个应用。

---

## 二、Package.swift：构建清单

整个项目的构建配置只有 19 行：

```swift
// swift-tools-version: 5.9
import PackageDescription

let package = Package(
    name: "FocusPet",
    platforms: [
        .macOS(.v14)
    ],
    targets: [
        .executableTarget(
            name: "FocusPet",
            path: "Sources/FocusPet",
            exclude: ["Info.plist"],
            resources: [
                .copy("PetAssets")
            ]
        )
    ]
)
```

逐项拆解：

| 配置 | 含义 |
| --- | --- |
| `swift-tools-version: 5.9` | 本包使用的 Swift 工具链最低版本，写在文件最顶上 |
| `name` | 包名，也是默认产物名（FocusPet 可执行文件） |
| `platforms: [.macOS(.v14)]` | 最低支持 macOS 14（Sonoma）。API 用到 14 的新特性时这里必须对齐 |
| `.executableTarget` | 可执行目标（对应还有 `.target` 库目标）。一个包可以有多个目标 |
| `path: "Sources/FocusPet"` | 源码目录（默认就是 `Sources/<目标名>`，写出来更明确） |
| `exclude: ["Info.plist"]` | Info.plist 不参与编译，但要放在目录里供打包脚本取用——告诉构建系统「忽略它」 |
| `resources: [.copy("PetAssets")]` | **本章重点**，下面单讲 |

### resources 与 Bundle.module

```swift
resources: [
    .copy("PetAssets")
]
```

这行告诉 SwiftPM：构建时把 `PetAssets` 目录原样拷贝进资源包。SwiftPM 会为每个带资源的 target 生成一个**配套的资源 bundle**（名字形如 `FocusPet_FocusPet.bundle`），构建产物里你会同时看到：

```
.build/debug/
├── FocusPet                  ← 可执行文件
└── FocusPet_FocusPet.bundle/ ← 资源包（里面装着 PetAssets/144 张 PNG）
```

代码里通过 `Bundle.module` 访问它（第 05 篇出现过）：

```swift
Bundle.module.url(forResource: "\(spec.prefix)_\(index)",
                  withExtension: "png",
                  subdirectory: "PetAssets")
```

`.copy` vs `.process`：前者原样拷贝（我们的 PNG 不需要任何处理），后者是 SwiftPM 的「智能处理」模式（会按平台优化图片等）。素材类资源用 `.copy` 最省事、行为最可预测。

## 三、Info.plist：应用的身份证

`Info.plist` 是一个 XML 格式的元数据文件，mac 系统在启动应用时要读它来回答一堆问题：这个包的可执行文件叫什么？bundle ID 是什么？图标是哪个？要不要显示在 Dock？

FocusPet 的完整 Info.plist 只有 30 行，关键键值：

| 键 | 值 | 管什么 |
| --- | --- | --- |
| `CFBundleIdentifier` | `local.focuspet.app` | 全球唯一 ID，系统用它区分应用。通知授权、单实例保护都认它 |
| `CFBundleExecutable` | `FocusPet` | `Contents/MacOS/` 下哪个文件是要运行的程序 |
| `CFBundleShortVersionString` | `0.6` | 用户看到的版本号 |
| `LSUIElement` | `true` | **菜单栏应用开关**：不显示 Dock 图标、不进 ⌘Tab。第 09 章那个「点击菜单要先 activate」的坑就是它带来的 |
| `CFBundleIconFile` | `AppIcon` | 应用图标（`Contents/Resources/AppIcon.icns`） |
| `LSMinimumSystemVersion` | `14.0` | 最低系统版本，与 Package.swift 的 platforms 呼应 |

注意它在 Package.swift 里被 `exclude` 了——因为它不是编译输入，而是**打包阶段的装配原料**。这是 SwiftPM 项目的常见手法：plist 放源码目录里跟着版本管理，打包时拷进 .app。

## 四、package-app.sh：把零件组装成 .app

`swift build` 只给你零件（二进制 + 资源 bundle + plist），`package-app.sh` 负责组装。逐段读：

```bash
#!/bin/bash
# 把 SwiftPM 产物包装成可运行的 .app（UserNotifications、自启等功能需要正式 bundle）
# 用法: ./package-app.sh [debug|release]   （默认 debug）
set -e
cd "$(dirname "$0")"
```

- `set -e`：任何命令失败立即退出脚本，不让错误静默累积。
- `cd "$(dirname "$0")"`：无论你在哪个目录调用这个脚本，都先切到脚本所在目录（项目根）。`$0` 是脚本自身的路径。

```bash
CONFIG="${1:-debug}"
APP=.build/$CONFIG/FocusPet.app
rm -rf "$APP"
mkdir -p "$APP/Contents/MacOS" "$APP/Contents/Resources"
```

- `"${1:-debug}"`：第一个命令行参数，缺省值 debug。`./package-app.sh release` 就出 release 版。
- `rm -rf` + `mkdir -p`：每次都从空目录组装，杜绝「上次打包的残留混进来」这种幽灵 bug。

```bash
cp .build/$CONFIG/FocusPet "$APP/Contents/MacOS/FocusPet"

# SwiftPM 资源包（帧动画素材）：Bundle.module 在 Bundle.main.resourceURL
# （即 Contents/Resources/）下查找
for b in .build/$CONFIG/*.bundle; do
    [ -e "$b" ] && cp -R "$b" "$APP/Contents/Resources/"
done

cp Sources/FocusPet/Info.plist "$APP/Contents/Info.plist"
```

这是 .app 目录结构的填充。标准 .app 布局：

```
FocusPet.app/
└── Contents/
    ├── Info.plist          ← 应用的身份证
    ├── MacOS/
    │   └── FocusPet        ← 可执行文件
    └── Resources/
        ├── AppIcon.icns    ← 图标
        └── FocusPet_FocusPet.bundle/  ← SwiftPM 资源包（素材在里面）
```

注释里那句是血泪知识：**`Bundle.module` 在运行时是从 `Bundle.main.resourceURL` 往下找的**——`Bundle.main` 是 .app 本身，它的 resourceURL 就是 `Contents/Resources/`。所以资源 bundle 必须落在 Resources/ 下，放错位置，144 张素材一张都找不到（PetView 会打出一排 `⚠️ 缺少素材`）。

```bash
cp "$(dirname "$0")/../FocusPetAssets/AppIcon.icns" \
   "$APP/Contents/Resources/AppIcon.icns" 2>/dev/null || true

# ad-hoc 签名（通知投递对签名有要求）；失败不阻断，直接运行通常也可工作
codesign --force --sign - "$APP/Contents/MacOS/FocusPet" 2>/dev/null || true
```

两处 `|| true` 是同一个哲学：**非关键步骤失败不阻断打包**。图标文件不在？先出个没图标的包。临时签名失败？多数功能照样能跑。对单人小项目，「包先出来」比「每一步都完美」重要。

### codesign --sign - 是什么

mac 的可执行文件需要「签名」才能享受全部系统服务（通知就是其一）。`--sign -` 是 **ad-hoc 签名**——「我自己给自己签，没有证书」。正式的开发者证书（Apple Developer Program，年费 99 美元）是用来发布到 App Store 或让他人无障碍运行的；自己机器上用 ad-hoc 足够。不签名或签名坏了的典型症状就是第 09 章那个：通知不工作，或系统弹「无法验证开发者」。

## 五、部署到 /Applications 并验证

打包出 `.build/release/FocusPet.app` 后，部署标准位置是 `/Applications`：

```bash
# 关掉运行中的旧版本，替换，重新打开
killall FocusPet 2>/dev/null || true
rm -rf /Applications/FocusPet.app
cp -R .build/release/FocusPet.app /Applications/
open /Applications/FocusPet.app
```

### 验证小技巧

**1. MD5 验证「我拷过去的到底是不是刚编译的」**

更新部署后如果行为没变，先别怀疑代码——可能是拷贝没生效或跑了旧进程：

```bash
md5 .build/release/FocusPet.app/Contents/MacOS/FocusPet
md5 /Applications/FocusPet.app/Contents/MacOS/FocusPet
```

两个哈希一致 = 文件确实是新的。不一致 = 部署环节出了问题。

**2. killall Dock 刷图标缓存**

更换 AppIcon 后，Finder 和 Dock 可能顽固地显示旧图标——那是系统的图标缓存没刷新：

```bash
killall Dock        # Dock 重启并重建缓存
killall Finder      # Finder 同理
```

若还不行，更彻底的方案是删 `~/Library/Caches/com.apple.iconservices.store` 后重启，但一般情况下重启 Dock 就够了。

**3. Release vs Debug 的行为差**

`swift build` 默认 debug：不做优化、带调试符号，**运行明显更慢更费电**。正式使用务必 `swift build -c release` 后再打包。省电版教程（第 14 篇）会再次强调这一点。

## 六、发布形态总结

```
源码 FocusPet/
  │
  │ swift build -c release
  ▼
零件：.build/release/FocusPet（二进制）
      .build/release/FocusPet_FocusPet.bundle（素材包）
  │
  │ ./package-app.sh release
  ▼
成品：.build/release/FocusPet.app（标准 bundle）
  │
  │ cp -R → /Applications
  ▼
运行中的菜单栏宠物 ✅
```

想分发给朋友？把 .app 压进 dmg 或 zip 即可；对方下载后可能需要在右键菜单里选「打开」以绕过 Gatekeeper（未付费公证的应用的必经一步）——这就是个人开发者发布 mac 应用的完整最小闭环。

## 练习

1. 故意把 `Info.plist` 的 `LSUIElement` 改成 `false`，重新打包运行，观察 Dock 的变化；再改回来。
2. 打包后把 `Contents/Resources/` 下的资源 bundle 改名，运行应用看 PetView 打印什么——亲眼看一次 `Bundle.module` 找不到资源的报错。
3. 用 `md5` 对比 debug 和 release 两个二进制，再对比各自的文件大小（`ls -lh`），体会 debug 携带的调试符号有多占地方。
4. 进阶：给 package-app.sh 加一行，打包后自动 `cp -R` 到 /Applications（记得先 killall）。体会「脚本化部署」省掉的机械劳动。
