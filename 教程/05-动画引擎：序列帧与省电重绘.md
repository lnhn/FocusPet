# 05 · 动画引擎：序列帧与省电重绘

> FocusPet 零基础开发教程 · 第 5 篇
> 对应源码：`PetView.swift` 全文（重点）

## 1. 帧动画的本质

所谓动画，就是**按时间顺序快速切换图片**。电影里是 24 帧/秒，我们的宠物：

```swift
struct AnimationSpec {
    let prefix: String       // 素材前缀，如 "walk" / "dog_walk"
    let count: Int           // 帧数（我们统一 8 帧）
    let frameDuration: CFTimeInterval   // 每帧停留秒数
    let holdLastExtra: CFTimeInterval   // 每轮最后一帧额外停留（制造节奏感）
    let repeatCount: Int?    // nil=无限循环；数字=播完停在最后一帧
}
```

猫走路 `0.6s/帧` → 慢悠悠；狗跑步 `0.14s/帧` → 飞奔。**换一个数字就换一种性格**，这是调动画手感的第一旋钮。

## 2. 播放状态机

PetView 内部维护一套极简状态：

```swift
private var frames: [NSImage] = []        // 当前动画的帧数组
private var frameIndex = 0                // 现在该画第几帧
private var frameStartTime: CFTimeInterval // 当前帧是几点开始播的
private var finished = false              // 有限循环播完了吗
```

推进逻辑（`tick`）：

```swift
if now - frameStartTime >= frameDurations[frameIndex] {
    frameIndex += 1
    frameStartTime = now
    if frameIndex >= frames.count {
        loopsDone += 1
        if 播够了 { finished = true; 回调 completion() }
        else { frameIndex = 0 }          // 回到第一帧，再来一轮
    }
}
```

核心思想：**不阻塞线程等待**，而是每次 tick 时问一句"该换帧了吗"。这叫"时间驱动"而非"延时驱动"，暂停、调速、跳帧都好做。

## 3. CVDisplayLink：跟着屏幕心跳走

```
屏幕每刷新一次（60Hz/120Hz）
  → CVDisplayLink 回调（在独立线程，极其精准）
  → 我们 dispatch 到主线程
  → 主线程执行 tick(now)
  → tick 里决定换不换帧、要不要重绘
```

为什么不用 `Timer`？Timer 受 RunLoop 模式影响（弹菜单时 Default 模式被切换，定时器会暂停），而 CVDisplayLink 跟着屏幕硬件走，**按屏幕实际刷新率回调**，精准且不停摆。

## 4. 素材加载：缓存是第一要务

```swift
func play(_ spec: AnimationSpec, ...) {
    if frameCache[spec.prefix] == nil {          // 首次播放才加载
        frameCache[spec.prefix] = (1...spec.count).compactMap { index in
            guard let url = Bundle.module.url(
                forResource: "\(spec.prefix)_\(index)",
                withExtension: "png",
                subdirectory: "PetAssets"
            ) else { print("⚠️ 缺少素材"); return nil }
            return NSImage(contentsOf: url)
        }
    }
    frames = frameCache[spec.prefix] ?? []
    ...
}
```

128 张 PNG 全加载约百来 MB 内存，8 套动画按需加载 + 永久缓存（宠物 app 跑一整天也不会换几套），是内存和速度的最优平衡。

## 5. 绘制一帧

```swift
override func draw(_ dirtyRect: NSRect) {
    NSGraphicsContext.current?.cgContext.clear(dirtyRect)
    let area = petArea
    drawFrame(frames[index], in: contentRect(for: frames[index], in: area))
    drawHearts(...); drawBubble(); drawHungerBubble()
}
```

`contentRect` 做的事：按区域等比缩放图片并居中，再叠加弹跳缩放系数：

```swift
let scale = bounceScale * min(
    (area.width - padding * 2) / image.size.width,
    (area.height - padding * 2) / image.size.height
)
```

水平镜像（向右走转身）用 CGContext 的 scale(-1,1) 实现，**不能用 flipped**（和 NSView 自带属性冲突）。

## 6. 跨帧过渡：重影问题的来龙去脉

帧与帧直接硬切，快速动画会显得"跳"。加 crossfade（两帧叠加渐隐）更顺滑，但会多画一张图；且如果**两帧素材没有像素级对齐**，叠加时轮廓会糊成"重影"。

我们的对策（素材层解决，见第 12 篇）：

1. 所有帧用**同一个裁剪框**（8 帧内容边界的并集），保证角色在每帧中的相对位置严格一致
2. 过渡时长动态计算：`min(0.08s, 帧时长×0.35)`，帧越快过渡越短
3. 视图保持非 layer-backed（第 4 篇）

## 7. 省电重绘：本项目的第二次大优化 ★

**问题**：CVDisplayLink 跟着 ProMotion 屏幕跑 120Hz，意味着每秒 120 次回调 + 120 次整窗重绘——哪怕宠物站着一动不动，GPU/CPU 也在空转。

**三层防线**（当前代码）：

```swift
// 第一层：回调里就过滤——没到换帧时刻，连主线程都不打扰
guard view.hasPendingWork(at: now) else { return kCVReturnSuccess }

// 第二层：tick 里比对——帧序号没变就不发 needsDisplay
if frameIndex != drawnFrameIndex {
    drawnFrameIndex = frameIndex
    needsDisplay = true
}

// 第三层：彻底静止就停表——动画播完、无弹跳、无爱心 → 停掉 DisplayLink
if !hasMotion { stopDisplayLink() }
// 恢复：play()/bounce()/showHearts() 里 startDisplayLink()
```

效果：待机时重绘频率从 120 次/秒降到 **3~4 次/秒**，静止时归零。

**通用心法**：动画系统的功耗 ∝ 重绘次数 × 重绘面积。优化永远是先减次数，再减面积，最后才考虑算法。

## 8. 爱心粒子系统（ mini 版粒子引擎 ）

双击时的爱心是"状态列表 + 每帧根据时间算位置"：

```swift
struct Heart { var x, y: CGFloat; var t0: CFTimeInterval; var emoji: String; ... }

// 绘制时（不是存储时）算位置：
let p = age / heartLife                 // 0→1 进度
let y = heart.y + p * 50 * viewScale    // 上升
let alpha = 1 - p * p                    // 渐隐
// 画完自动清理过期粒子
```

粒子系统的通用范式就是这三步：**发射（append）→ 推进（按时间算状态）→ 回收（removeAll）**。
