# 06 · 行为调度：让宠物「活」起来

> FocusPet 零基础开发教程 · 第 6 篇
> 对应源码：`PetController.swift` 的行为调度部分

## 1. 目标

宠物不能只是循环播放待机动画——那是个屏保。我们要它**自己决定接下来干嘛**。拆解一下"活着"的感觉：

- 大多数时候待着（idle）
- 偶尔起来走两步（散步 stroll）
- 偶尔突然疯跑（乱窜 dash）
- 有事时（专注/被拖拽）停下一切
- 饿了就讨食

全部是**「随机数决定做什么 + 定时器决定何时做」**。没有人工智能，但效果以假乱真。

## 2. 调度器的通用骨架

项目里有两类调度，结构一模一样：

```swift
// 类型一：随机小动作（DispatchWorkItem 版）
private func scheduleRandomBehavior() {
    idleWorkItem?.cancel()                          // ① 取消旧的
    let delay = Double.random(in: 5...12)           // ② 随机等待
    let item = DispatchWorkItem { [weak self] in
        self?.performRandomBehavior()               // ③ 到点执行
    }
    DispatchQueue.main.asyncAfter(deadline: .now() + delay, execute: item)
    idleWorkItem = item                              // ④ 记住它，方便取消
}

// 类型二：乱窜（Timer 版，逻辑相同）
private func scheduleRoam() {
    roamTimer?.invalidate()
    roamTimer = Timer.scheduledTimer(withTimeInterval: Double.random(in: 12...30),
                                     repeats: false) { [weak self] _ in
        self?.performRoam()
    }
}
```

**记住这个四步骨架**：取消旧 → 随机延迟 → 执行 → 存引用。它是所有"周期性随机行为"的模板（讨食调度也是照抄的）。

## 3. 行为决策：掷骰子

```swift
switch Int.random(in: 0..<10) {
case 0...4:  performStroll()     // 50% 散步（最常见，闲不住）
case 5...6:  play(.wave) {...}   // 20% 挥手
case 7...8:  play(.sleep) {...}  // 20% 趴下睡会儿
default:     break               // 10% 继续待着
}
```

调概率就是调性格。想让它更粘人？把 wave 的概率调高。这就是"游戏手感调校"。

## 4. 移动：一次完整的散步是怎么实现的

`startMove(.stroll)` 的核心参数（猫 vs 狗）：

| 参数 | 猫 | 狗 | 效果 |
|---|---|---|---|
| 速度 | 55~95 px/s | 130~190 px/s | 猫遛弯，狗赶路 |
| 帧时长 | 0.6s | 0.26s | 猫抬腿慢，狗倒腾快 |
| 抛物线高度 | ≤14px | ≤60px | 狗明显在蹦 |

**插值移动**（每 16ms tick 一次）：

```swift
let raw = (CACurrentMediaTime() - roamT0) / roamDur   // 0→1 进度
let e = raw < 0.5 ? 2 * raw * raw : 1 - pow(-2 * raw + 2, 2) / 2  // easeInOut
panel.setFrameOrigin(NSPoint(
    x: from.x + (to.x - from.x) * e,
    y: from.y + (to.y - from.y) * e + roamArc * sin(.pi * raw)  // 抛物线
))
```

两个数学小动作值得记住：

1. **easeInOut**：起步慢、中间快、停稳慢。直接线性移动（`x = from + (to-from)*raw`）会像机器人滑轨；`2t²` / `1-(-2t+2)²/2` 这两段二次函数让移动有"重量感"
2. **`sin(π·raw)`**：0→1 之间正好是「0 升到 1 再落回 0」的光滑弧线，加在 y 上就是蹦跳

**到达处理**：

```swift
if raw >= 1 {
    panel.setFrameOrigin(to)      // 精确落点（防浮点误差）
    timer.invalidate()
    if 有庆典回调 { 执行庆典 } else { 回 idle }
    scheduleRoam()                // 排下一次乱窜
}
```

## 5. 打断与礼让：多调度器共存不打架

三个调度器可能同时想要宠物：随机小动作、乱窜、讨食。规则：

```swift
guard roamAnim == nil else { return }        // 移动中不启动新移动
guard !petView.isBeingDragged else { ... }   // 被拖拽时全部避让
guard !isSessionActive() else { return }     // 专注时暂停自由行为
```

**会话状态是最高优先级**：`onSessionStart` 一口气取消 idleWorkItem 和 roamTimer；`onSessionEnd` 再重新调度。这就像红绿灯——不是每个司机互相让，而是大家都听信号灯。

## 6. 庆典移动：复用的胜利

"专注结束跑到屏幕中央"和散步/乱窜本质是同一件事（从 A 到 B）。我们给移动系统加了一个到达回调插槽：

```swift
private var onArriveMove: (() -> Void)?

// 到达分支：
if let cb = self.onArriveMove {
    self.onArriveMove = nil
    cb()                                   // 接庆祝
} else if !self.isSessionActive() {
    self.play(.idle)
}
```

`celebrateAtScreenCenter` 只是"设好目标点 + 挂上回调"——移动代码零重复。这就是第 3 篇说的"在中间加一根线"。

## 7. 踩坑实录：那次庆典没跑起来

最初实现庆典时，设好了目标坐标和速度，却忘了启动移动 Timer——宠物原地庆祝，休息照常。冒烟测试靠日志（"跑去屏幕中央庆祝！距离 817pt"之后没有"休息开始"）抓住了它。

**教训**：跨组件的新流程，一定要写"端到端冒烟测试"——不是测函数，而是模拟真实用户把流程走一遍。
