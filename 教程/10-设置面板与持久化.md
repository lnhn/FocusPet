# 10 · 设置面板与数据持久化

> FocusPet 零基础开发教程 · 第 10 篇
> 对应源码：`Sources/FocusPet/SettingsModel.swift`（123 行）、`Sources/FocusPet/SettingsView.swift`（180 行）

「设置」是所有应用躲不开的标配。它背后有两个经典问题：**数据放哪？（持久化）** 和**界面怎么写？（设置面板）**。本章用 FocusPet 的方案把两个问题一次讲透。好消息是：设置面板是这个项目里**唯一用到 SwiftUI** 的地方——你在第 02 篇学过的 SwiftUI 知识（`VStack`、`@State`、`$` 绑定）将全部派上用场。

## 一、持久化选型：UserDefaults

设置数据的特征很明确：量少（十几个值）、结构简单（数字、开关、字符串）、读写频繁。这种数据的标准归宿是 **UserDefaults**——mac 系统提供的轻量键值存储。

UserDefaults 的用法简单到不像话，就三个动作：

```swift
let defaults = UserDefaults.standard

defaults.set(45, forKey: "focusMinutes")          // 写
let minutes = defaults.double(forKey: "focusMinutes")  // 读
defaults.removeObject(forKey: "focusMinutes")     // 删
```

它本质上是一张「字符串键 → 任意值」的字典，由系统自动落盘到 `~/Library/Preferences/` 下的一个 plist 文件。你不用管文件路径、不用管序列化、不用管什么时候写盘——系统替你全包了。

### 一个读写的类型陷阱

读的时候有个著名的坑。看 SettingsModel 初始化里的读法：

```swift
focusMinutes = defaults.object(forKey: Keys.focusMinutes) as? Double ?? 25
```

为什么不直接写 `defaults.double(forKey:)`？因为 `double(forKey:)` 在**键不存在时会返回 0**——你无法区分「用户存了 0」和「从来没存过」。而 `object(forKey:)` 返回可选值：键不存在就是 `nil`。于是 `as? Double ?? 25` 的完整语义是：

> 「如果存过且确实是 Double，用它；否则（含从来没存过的情况）用默认值 25。」

首次启动的应用没有任何历史设置，这行代码保证每个字段都有合理的出厂值。这就是「默认值兜底」模式，UserDefaults 编程天天用。

### 键名集中管理

```swift
private enum Keys {
    static let focusMinutes = "focusMinutes"
    static let shortRestMinutes = "shortRestMinutes"
    ...
}
```

把所有键名收进一个私有枚举，好处有二：一是避免手滑打错字符串（`"foucsMinutes"` 这种 typo 编译器可发现不了）；二是键清单一目了然。`private` 修饰保证只有 SettingsModel 内部能用这些键——**键的命名空间是模型私有的**，外界不应该绕过模型直接读写。

## 二、@Published + didSet：数据变动的双通道

SettingsModel 是一个 `ObservableObject`（第 02 篇的概念：「可被观察的对象」），它的每个属性都挂着两个装饰器：

```swift
@Published var focusMinutes: Double {
    didSet { UserDefaults.standard.set(focusMinutes, forKey: Keys.focusMinutes); notify() }
}
```

这一行里塞了三层机制，层层都有明确职责：

| 机制 | 干什么 |
| --- | --- |
| `@Published` | 告诉 SwiftUI「这值变了请刷新界面」——数据 → 界面的通道 |
| `didSet`（属性观察器） | 每次赋值后自动执行：写入 UserDefaults（持久化）+ 调 `notify()`（通知 AppDelegate 即时生效） |
| `notify()` → `onChange` | 让 AppDelegate 立刻把新值应用到引擎、宠物尺寸等——数据 → 业务逻辑的通道 |

也就是说，**一次赋值触发三条路**：界面刷新、磁盘落盘、业务生效。用户在设置面板里拖一下滑杆，三路人马同时开动，这就是设置窗口底部那句「所有设置即时生效」的技术底气。

三条路里两条是 Swift 内建机制（`@Published`、属性观察器），第三条（`onChange` 回调）是我们自己加的——因为有些设置 SwiftUI 管不到（比如 FocusEngine 的时长、状态栏热键的注册注销），必须靠 AppDelegate 手动应用。

### Date? 的可选值持久化

日期类设置（生日、纪念日）是 `Date?`，存储时转成时间戳（Double）：

```swift
private func saveOptional(_ date: Date?, key: String) {
    if let date {
        UserDefaults.standard.set(date.timeIntervalSince1970, forKey: key)
    } else {
        UserDefaults.standard.removeObject(forKey: key)
    }
}
```

`Date` 不能直接塞进 UserDefaults（实际上可以，但跨版本兼容性不如原始 Double 稳），而「从 1970 年到现在的秒数」这个 Double 存哪都安全。nil 则对应**删除键**——UserDefaults 里没有「null」概念，「没设过」和「设为空」是同一个状态。

## 三、设置面板：SwiftUI 的一次完整实战

打开 `SettingsView.swift`，从上到下能看到 SwiftUI 的常用控件全家桶：

### 3.1 声明式布局

```swift
var body: some View {
    VStack(spacing: 16) {
        GroupBox("番茄钟节奏") {
            VStack(spacing: 10) {
                Stepper("专注时长：\(Int(model.focusMinutes)) 分钟",
                        value: $model.focusMinutes, in: 5...120, step: 5)
                ...
```

- `VStack(spacing:)`：竖着排，子项间距 16 点。想要横排就换 `HStack`。
- `GroupBox("标题") { ... }`：mac 原生风格的分组卡片——标题在左上，内容包在圆角框里。设置类界面的标准件。
- `Stepper`：步进器，点 +/- 调数字。`value: $model.focusMinutes` 是双向绑定，`5...120` 是值域，`step: 5` 是步长。
- `some View`：返回类型占位，意思是「某种视图，具体哪种编译器自己推」。

标签里的 `\(Int(model.focusMinutes))` 是字符串插值——`model.focusMinutes` 是 Double（25.0），`Int(...)` 转成整数显示成「25 分钟」。

### 3.2 绑定：$ 号的一往一返

这是 SwiftUI 最核心的概念，值得再强调一次。`model.focusMinutes` 前面加 `$`：

```
$model.focusMinutes  ←→  一个 Binding<Double>
```

`Binding` 是个「读写双向通道」：控件读出它显示当前值；用户操作时通过它写回新值。写回时触发什么？——上一节的 `@Published` + `didSet` 三通道全开。所以从「用户拖滑杆」到「引擎拿到新时长」的完整链路是纯声明式的，**你没有写一行事件处理代码**。

### 3.3 一个宠物、两套资料：计算型绑定

项目里有个小麻烦：猫和狗各有名字和生日（共 4 个存储字段），但界面上一次只展示当前选中宠物的那套。滑杆切到「狗狗」就该编辑 `dogName`，切回「猫咪」编辑 `catName`。`TextField` 需要一个 `Binding<String>`，可它绑哪个？

解法是自己造一个「分流绑定」：

```swift
private var nameBinding: Binding<String> {
    Binding(
        get: { self.model.selectedPet == "dog" ? self.model.dogName : self.model.catName },
        set: { newValue in
            if self.model.selectedPet == "dog" {
                self.model.dogName = newValue
            } else {
                self.model.catName = newValue
            }
        }
    )
}
```

`Binding` 可以手动构造：给个 `get`（读时去哪取）和 `set`（写时存到哪）。控件无感知——它只认「这是个 Binding」，背后分流到猫还是狗它不关心。这是「**适配器模式**」的 SwiftUI 版：接口不变，内部按需转换。

### 3.4 可选日期：开关 + 选择器的组合

生日是可选的（`Date?`），但 SwiftUI 的 `DatePicker` 只接受非可选的 `Date`。`optionalDatePicker` 这个自定义组件把「有没有生日」翻译成界面上一个开关：

```swift
Toggle(label, isOn: Binding(
    get: { date.wrappedValue != nil },
    set: { date.wrappedValue = $0 ? Date() : nil }   // 打开 = 填上今天；关闭 = 清空
))
if date.wrappedValue != nil {
    DatePicker("", selection: Binding(
        get: { date.wrappedValue ?? Date() },
        set: { date.wrappedValue = $0 }
    ), displayedComponents: .date)
}
```

又一个手工 Binding：开关的「开/关」和日期的「有/无」互相翻译。开关打开时默认填「今天」（省得用户滚半天日期），出现日期选择器；关掉则清空并隐藏选择器。界面呈现和数据模型之间这种「展示态 ↔ 存储态」的自由转换，就是 Binding 手工构造的典型战场。

`@ViewBuilder trailing:` 参数是另一个进阶点——让调用方用 SwiftUI 语法块传入「日期下方的附加内容」（星座、相伴天数），这个写法叫 **ViewBuilder 尾随闭包**，你可以先跳过，用到时再学。

## 四、窗口的呈现：AppKit 里嵌 SwiftUI

设置面板是 SwiftUI 写的，但应用主体是 AppKit。两者怎么合体？答案在第 02 篇预告过的 **NSHostingController**——把 SwiftUI 视图装进 AppKit 窗口：

```swift
// AppDelegate 里的呈现逻辑（节选）
let controller = NSHostingController(rootView: SettingsView(model: settings))
settingsPanel.contentViewController = controller
settingsPanel?.makeKeyAndOrderFront(nil)
```

`NSHostingController` 是 SwiftUI ↔ AppKit 的官方桥：给它一个 SwiftUI 视图，它就能像普通 AppKit 视图控制器一样塞进 `NSWindow`。所以本项目的真实技术栈是：**AppKit 为骨（窗口、面板、事件），SwiftUI 为皮（设置、统计界面）**。这样的混搭在 mac 开发里极其常见——老代码增量迁移到 SwiftUI 就靠这座桥。
