# 12 · AI 素材生产管线：从一句话到 144 帧动画

> FocusPet 零基础开发教程 · 第 12 篇
> 对应素材：`Sources/FocusPet/PetAssets/`（144 张 PNG 序列帧）

这一章有点特别：前面十一篇讲的都是写代码，这一篇讲**怎么造出代码要用的素材**。FocusPet 里猫咪和狗狗的全部动画不是美术软件画的，而是 AI 生成的。最终成果：

| 宠物 | 动画组 | 每组帧数 | 小计 |
| --- | --- | --- | --- |
| 🐱 猫咪 | idle / walk / run / sleep / focus / celebrate / wave / sad / eat | 8 | 72 |
| 🐶 狗狗 | 同上，文件名加 `dog_` 前缀 | 8 | 72 |
| **合计** | 18 组 | | **144 帧** |

这一章把整套管线拆开：提示词怎么写 → 一次生成 8 帧 → 切片 → 去底 → 修洞。每一步都有真实踩过的坑。

---

## 一、总体管线

```
① 写提示词 → ② AI 生成一张 8 格网格图 → ③ 按统一网格切成 8 帧
     ↓                                              ↓
④ 白底转透明（去底）→ ⑤ 修透明洞 → ⑥ 按 前缀_序号.png 命名入库
```

为什么要「一张图 8 格」而不是直接生成 8 张单独的图？两个原因：

1. **一致性**。让 AI 分别画 8 张「同一只猫」，每张都会长不一样；而一张图里的 8 格，角色基本是同一个。动画帧之间角色形状必须稳定，否则播起来像「跳变」而不是「动」。
2. **效率**。生成一张大图比生成 8 次、每次还要祈祷角色不变，省时得多。

## 二、提示词的写法

提示词（prompt）是与 AI 绘图模型沟通的语言。写动画帧提示词的核心原则是：**把「美术要求」全部说死，把「变化」只留给动作本身**。

一套可直接套用的模板（本项目实际使用的写法，可按你的宠物随意改）：

```
A cute kawaii [橘色虎斑小猫 / 棕色小狗], [动作描述，如：idle animation,
gentle breathing with tail swaying], simple flat cartoon style, thick clean
outline, full body centered in each cell, consistent character design across
all cells, pure white background, no shadow, no watermark, no text,
4x2 grid layout with 8 equal cells, each cell shows one frame of the animation
in sequence
```

逐块拆解，每块都对应一个真实的需求：

| 提示词片段 | 防止的灾难 |
| --- | --- |
| `kawaii ... simple flat cartoon style` | 防止 AI 画成写实风（写实风序列帧有一点抖动就瘆人） |
| `consistent character design across all cells` | 防止 8 格画出 8 只不同的猫 |
| `full body centered in each cell` | 防止角色出框——出框的帧切出来就是「缺腿猫」 |
| `pure white background, no shadow` | 为下一步「去底」创造条件：纯白底最容易程序化移除 |
| `no watermark, no text` | 防止画面角落出现乱码字母（AI 签名癖） |
| `4x2 grid layout with 8 equal cells` | 让 8 帧排成规则网格，程序才能按统一坐标切 |

### 动作描述的措辞

每个动画组只改模板里的动作部分。写动作时的关键认知：**AI 不理解「动画」，它理解的是「8 个略有差别的静态姿势」**。所以动作描述要描述「这一组姿势整体在干什么」，而不是「从 A 到 B 的过程」。实际使用过的描述风格：

| 组 | 动作描述思路 |
| --- | --- |
| idle | 轻轻呼吸、尾巴缓慢摆动（变化极小，8 帧几乎像静图） |
| walk | 走路循环，四腿交替迈步（猫：慢、慵懒；狗：快、蹦跳感） |
| run | 快速奔跑，身体拉伸 |
| sleep | 趴着，Zzz 式起伏（可以偶尔带一个呼噜气泡，但注意别带文字） |
| focus | 正襟危坐、表情认真（配合番茄钟专注状态） |
| celebrate | 跳跃、双爪举起、开心 |
| wave | 举爪招手 |
| sad | 垂耳低头、沮丧（用于用户中途放弃专注） |
| eat | 低头啃食盆、咀嚼 |

猫和狗的**走路节奏差异**是在提示词阶段就定下的：猫的 walk 描述里加 `slow, lazy, relaxed pacing`，狗的 walk 里加 `bouncy, energetic, happy trotting`。这也是后来代码里猫帧时长 0.6 秒、狗 0.26 秒的底气（第 06 篇讲过）。

### 参考图：系列一致性的大招

画完猫之后要画狗、或者要画同一只猫的第二个动作组，最怕的是「两只猫」。解法是给 AI 一张**参考图**（image reference）：上传已生成、效果满意的角色图，让新图「照着这只画」。本项目所有动画组的角色一致性就是这么维持的。写提示词时把参考图放在最前面，再补一句 `same character as the reference image`。

## 三、切片：统一裁剪框

AI 交出的是一张 4×2 网格大图。切成 8 帧的程序化思路：

```
整张图宽 W、高 H，则每格宽 W/4、高 H/2
第 n 帧（n 从 0 数到 7）的格子坐标：
    列 = n % 4    （第几列）
    行 = n / 4    （第几行，整除）
    裁剪框 = (列 × W/4, 行 × H/2, W/4, H/2)
```

用 Pillow（Python 图像库）十几行就能写完。要点只有两个：

1. **统一裁剪框**：所有帧组用同一套相对坐标切，保证切出来的角色位置一致——位置不一致，播放时角色会在原地「抖」。
2. **切完人工抽查**：程序切完，务必把 8 帧按顺序快速翻看一遍（Mac 上选中 8 张图按空格预览，来回按方向键）。AI 偶尔会画出 7 格或 9 格、或某格里角色出框，这类问题只有肉眼能发现，发现就重新生成这一组，别试图修。

## 四、去底与修洞：两个大坑

### 4.1 坑一：去底不能简单「去白」

切片后是白底。转透明（俗称去底）的最朴素想法：把所有接近白色的像素变透明。这里埋着本项目最阴的坑——**有些猫是乳白色、奶白色的**。「接近白」的阈值稍微激进一点，就会把猫身上的浅色毛发一起删掉，切出来的 PNG 上赫然出现**透明的洞**。

### 4.2 坑二：「智能去水印」会制造洞

还有一种看起来更高级的坑。AI 生成的图有时带模型水印或角落的乱码签名，会引入一种叫 `clean_watermark` 的去水印工具/功能。它的原理是识别「重复出现的图案」并抹除——问题就在「重复」二字：**动画帧里角色的重复出现被它当成了水印**，一抹，角色身上又多了透明区域。

### 4.3 修法：BFS 边界洪水填充

正确的去底姿势不是「全图删白」，而是**洪水填充（Flood Fill）**：

> 只从**图像四边**出发找连通的白色区域删除，图像内部的白色（哪怕和边缘白只有一条细线连着也得靠「连通」来判断）一律不碰。

用 BFS（广度优先搜索，第 01 篇提过队列思想）实现：

```
1. 把四边上所有白色像素入队，标记为「待删」
2. 循环：出队一个像素 → 检查它的上下左右四邻居
   - 邻居是白色且未标记 → 入队、标记
3. 队列空后，把所有「待删」像素置为透明
```

因为搜索**只从边缘出发**，宠物身体内部的乳白毛发哪怕颜色和白底一模一样，也隔着一层有颜色的轮廓线， flood fill 根本到不了它——洞的问题从原理上被根除。

如果某些帧还是不幸带了洞（比如白底和毛发之间真有缺口连通），修复思路也基于同一个原理的逆运用：从洞的边缘往里填色，而不是从全图删色。

### 4.4 工程顺序的建议

```
先生成 → 再切片 → 先检查有没有水印 → 有水印重生成（别用去水印工具）
→ 边缘洪水填充去白底 → 抽查 → 入库
```

「能重新生成就别修图」是 AI 素材时代的黄金法则：提示词改一改重新抽一张，往往比 PS 半小时快得多、效果也好得多。

## 五、命名与入库：和代码的契约

最终文件名严格遵守代码的约定（第 05 篇的 `AnimationSpec`）：

```
猫咪：idle_1.png ... idle_8.png      （无前缀 = 默认猫）
狗狗：dog_idle_1.png ... dog_idle_8.png
```

这个「猫无前缀、狗加 `dog_`」的约定意味着：**代码里所有猫咪的动画组一行不用改**，狗的素材加前缀就共存了。给素材命名时脑子里要有代码——`prefix` 对应文件名前缀，动画组在代码里加一个 `static let` 就接入完成（第 06 篇练习 3 做过这个）。

素材目录 `PetAssets/` 直接放在 `Sources/FocusPet/` 下，随 SwiftPM 打包（第 13 篇详解），`PetAssets.zip` 留一份压缩备份，方便整体迁移（比如后来做 Windows 版时直接拷走）。

## 六、给非美术程序员的整体建议

| 阶段 | 建议 |
| --- | --- |
| 提示词 | 说死一切风格要求，只留动作一个变量；同角色必用参考图 |
| 生成 | 一次不满意就重抽，提示词是彩票，多买几张 |
| 切片 | 统一裁剪框 + 人工逐帧抽查，两者缺一不可 |
| 去底 | 只信边缘洪水填充，不信「全图删白」和「智能去水印」 |
| 命名 | 命名前先读代码的文件查找逻辑，命名即契约 |

这套管线跑通一次后，新增一个动画组（比如后来的 eat）的成本大约是：写一段动作描述 → 生成 2~3 张挑一张 → 切片抽查 → 去底 → 放进目录 → 代码里加一个 `AnimationSpec`。**半小时内，宠物就学会了一个新动作。**

## 练习

1. 用本章的提示词模板，给你自己的桌面宠物生成一组 idle 动画（任何你顺手的 AI 绘图工具），按 4×2 网格要求检查输出。
2. 用 Pillow 写一个切片脚本：输入一张 4×2 网格大图，输出 8 张 `test_1.png` ~ `test_8.png`。
3. 实现边缘洪水填充去白底，并故意找一张有浅色主体（白云、白猫）的图，对比「全图删白」和「洪水填充」的结果差异。
4. 思考题：如果 AI 只愿意输出 3×3 九宫格，切片公式要怎么改？（提示：`%` 和 `/` 的除数变了。）
