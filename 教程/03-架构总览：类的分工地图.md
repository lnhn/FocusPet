## 设计模式 1：回调解耦（最重要的模式）

类之间**不互相持有**，只留"插槽"：

```swift
// FocusEngine 不知道 PetController 存在，只广播"会话开始了"
final class FocusEngine {
    var onSessionStart: ((Session) -> Void)?
}
// AppDelegate 把两边接上：
engine.onSessionStart = { [weak self] session in
    self?.pet?.onSessionStart(isRest: session.kind.isRest)
}
```

好处：番茄钟引擎可以单独测试、单独复用；改宠物不影响计时逻辑。新增功能时，大部分情况是"在中间加一根线"，而不是"改两边的代码"。

## 设计模式 2：状态由"数据"驱动

宠物的所有外观状态都收在两个枚举里：

```swift
enum PetAction: String, CaseIterable {
    case idle, wave, sleep, focus, celebrate, sad, run, walk, eat
}
enum Phase { case idle, running, paused }   // FocusEngine 的
```

菜单标题、动画选择、气泡显示，全部是对这两个枚举的 `switch`。想加新状态（比如"洗澡"），只需：枚举加一个 case → 素材加一套 → switch 补几个分支。

## 设计模式 3：单一职责到极致

注意 `PetController` 和 `PetView` 的分工：

- **Controller 决定"播什么、去哪"**（调用 play(.walk)、设置目标点）
- **View 只负责"画出来"**（拿到帧数组就画，不知道为什么要画）

这就是经典的 MVC（Model-View-Controller）。View 永远不写业务逻辑，所以换皮（换物种）不用动 View。

## 数据流：一次专注的完整旅程

```
用户点「开始专注」
 → AppDelegate.startFocus()
 → FocusEngine.startFocus()：phase=running，每秒 onTick
 → AppDelegate：onTick 里更新气泡文字 "24:59"
 → （25分钟后）onSessionComplete
 → AppDelegate：notify() 发系统通知 + NSSound 提示音
 → AppDelegate：pet?.celebrateAtScreenCenter { engine.startRest() }
 → PetController：跑过去 → bounce → play(.celebrate)
 → 庆祝播完 → 回调触发 → engine.startRest() 进入休息
 → StatsStore.add(record) 落盘
```

每一根箭头都是一次回调调用。跟着这个流程读源码，30 分钟就能串起整个项目。
